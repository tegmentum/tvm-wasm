# Contributing

## Build & test

The default `cargo test --workspace` runs everything that doesn't need a
wasm32 toolchain. The end-to-end guest tests will silently skip if the
target isn't installed:

```sh
rustup target add wasm32-unknown-unknown
cargo test --workspace
```

Single-crate runs:

```sh
cargo test -p tvm-core           # directory, allocators, metrics, cache
cargo test -p tvm-wasmtime       # WIT host, raw linker, runtime spill
cargo test -p tvm-tests          # cross-crate integration coverage
```

## Workspace layout

```
crates/
  tvm-core/         Pure-Rust core. No wasmtime or wit-bindgen deps.
  tvm-wasmtime/     Wasmtime host: WIT bindings, raw linker, SharedTvmHost.
  tvm-guest-rt/     Guest-side helper crate. Builds for both host and wasm32.
  tvm-tests/        Integration tests for tvm-core (no wasmtime).

examples/
  guest-demo/         WIT-path guest. Uses wit-bindgen.
  guest-fast-path/    Raw-path guest. Uses tvm-guest-rt.

wit/
  tvm.wit             Production WIT package.
  demo.wit            Development-only world for end-to-end tests.

docs/
  architecture.md     What's actually built.
  fast-paths.md       When to use WIT vs raw, with cost analysis.
```

`examples/` are excluded from the workspace because they target wasm32.

## Regenerating WIT bindings

Bindings are generated by macros at compile time:

- Host bindings: `wasmtime::component::bindgen!` in
  `crates/tvm-wasmtime/src/bindings.rs`.
- Guest bindings: `wit_bindgen::generate!` in
  `examples/guest-demo/src/lib.rs`.

When `wit/*.wit` changes, just rebuild — the macros pick it up. If a guest
example uses `with:` to map types from another world, ensure the bindgen
invocation references the correct world name.

## Adding a region kind

1. Add the variant to `RegionKind` in `crates/tvm-core/src/region.rs` and to
   `wit/tvm.wit` types interface.
2. Add a `PlacementPolicy::for_kind` arm.
3. Update the host conversion functions in `crates/tvm-wasmtime/src/host.rs`
   (`to_core_kind` / `from_core_kind`).
4. Add the variant to `tvm-guest-rt/src/lib.rs::RegionKind` (the discriminant
   must match bindgen's order).

## Adding a backing store

Implement `BackingStore` in `crates/tvm-core/src/backing.rs`:

```rust
pub trait BackingStore {
    fn spill(&mut self, region_id: u16, generation: u16, bytes: &[u8]) -> Result<()>;
    fn load(&mut self, region_id: u16, generation: u16) -> Result<Vec<u8>>;
}
```

Wire into `TvmHost::with_backing` if you want it reachable from the WIT
manager interface. The manager only knows about `FileBackingStore` today —
generalizing requires either a `Box<dyn BackingStore>` (allocates per call)
or making `TvmHost` generic over the backing type.

## Style

- Tests live with their feature: per-feature integration files under
  `tvm-tests/tests/` and unit tests inline with `#[cfg(test)]`.
- New WIT features need a corresponding test that goes through the bindgen
  trait, not just the underlying core method.
- Avoid `unwrap()` in production code paths; tests are fine.

## Running benchmarks

```sh
cargo bench -p tvm-wasmtime
```

The benchmarks live in `crates/tvm-wasmtime/benches/`. They use criterion;
results land in `target/criterion/`.

## Filing issues

Include the milestone (M9–M15) the issue relates to if you can. The plan
lives in this repo's issue tracker / commit history; the architecture doc
points at what's currently built vs deferred.
